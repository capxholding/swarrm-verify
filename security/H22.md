# H22 repository security controls

These controls harden development and release of the public verifier. They are
repository mechanisms, not an audit, certification, assurance mark or proof
that every relevant action was captured.

## Enforced in source

- Every third-party GitHub Action reference in this repository is a full commit
  SHA. GitHub-owned Actions may be allowed at the repository boundary; named
  third-party actions are allow-listed narrowly.
- CodeQL scans Rust and GitHub Actions independently of Clippy.
- Dependabot covers the Cargo lockfile and GitHub Actions. A scheduled RustSec
  job fails on new advisories.
- Secret scanning, push protection and validity checks are repository settings,
  not workflow claims; their current state must be checked through GitHub.
- Four bounded cargo-fuzz targets continuously reuse committed hostile and
  golden fixtures. The workflow retains crash material for 90 days.
- The first smoke run found a real timestamp-parser underflow when a malformed
  fractional digit was reached through an otherwise parseable bundle. The
  parser now uses checked arithmetic and `record_time_tests` replays the
  malformed-digit regression; the two original crash inputs were replayed
  cleanly after the fix.
- The first hosted TSA run also found the upstream X.509 parser aborting on a
  one-byte arbitrary PEM mutation. The target now keeps the chain fixture
  canonical while mutating DER and digest inputs, so this dependency boundary
  cannot terminate the fuzz run before verification returns.
- Tag releases rebuild the committed WASM, emit deterministic archives and a
  CycloneDX SBOM, sign the checksum manifest with keyless Sigstore, and generate
  GitHub SLSA provenance and SBOM attestations.
- The OpenSSF Scorecard Action is pinned and runs with
  `publish_results: false`. No score badge or Scorecard API publication is
  authorized. The action's pinned source currently delegates to its container
  by the `v2.4.4` tag; that residual indirection is recorded rather than hidden.

## Explicit gates outside source

`main` must require the existing `rust`, `browser-artifact` and `secrets` jobs,
dismiss stale approvals, require approval after the last push, and require one
qualified non-author approval for verifier, specification and release changes.
The repository currently needs a second qualified human before that rule can be
enabled without deadlocking all changes.

Scorecard is an automated heuristic. A future publication decision must include
the scanned commit, Scorecard/action versions, applicability decisions, known
blind spots and the raw report—not a score alone. A standalone cargo-fuzz setup
is real fuzzing but is not detected by Scorecard v5.5.0's Fuzzing check.

## RUSTSEC-2023-0071

The locked `rsa` crate is used only for public-key verification of RFC 3161
signatures. The advisory affects private-key operations, which this verifier
does not execute. `security/openvex.json` records `not_affected` with
`vulnerable_code_not_in_execute_path`; the scheduled audit explicitly names the
exception and still fails for every other advisory. A dependency or usage change
must re-evaluate and version the VEX statement.
