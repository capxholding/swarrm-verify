Swarrm public verifier — build integrity
=========================================

The verifier that runs in your browser must be auditable: you should be able
to confirm the WASM you are served is the one built from this repo's source
(verify-rs/), and not a silently substituted one.

Reproduce and check:

    cd verify-rs
    tool_bin=$(bash scripts/install-canonical-wasm-tools.sh /tmp/swarrm-wasm-tools)
    PATH="$tool_bin:$PATH" bash scripts/build-canonical-wasm.sh web
    shasum -a 256 pkg/swarrm_verify_bg.wasm

Expected sha256 of swarrm_verify.js (the canonical x86_64 Linux CI build
from this source tree):

    4ce489e429e22ae87626e0f4ba326970ca679867011b00aee3b198d9d0bd88cb

Expected sha256 of swarrm_verify_bg.wasm (the canonical x86_64 Linux CI build
from this source tree):

    1a2cbf80a55b37efca5107d659fbf721af537e676db6f81247768e34570e2604

This artifact was rebuilt on x86_64 Linux with Rust 1.90.0 and checksummed
wasm-pack 0.15.0, wasm-bindgen CLI 0.2.126 and Binaryen 117 release binaries.
CI asserts exact-byte reproduction on that host; other host platforms can
produce semantically equivalent but byte-different modules.
The page hardcodes both release digests and refuses to execute the JS glue or
instantiate the WASM unless their bytes match. This file is reproducibility
context, not the browser's source of expected values. The verifier is
client-side only and does not upload a bundle you choose. The pins do not by
themselves audit the source, authenticate the page that displays them,
establish external trust roots, or prove capture completeness.
